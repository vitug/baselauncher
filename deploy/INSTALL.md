# BaseLauncher — поставка (версия {VERSION})

Свой стартер баз 1С: список баз из `ibases.v8i`, режимы Предприятие/Конфигуратор, живой
статус сеансов, избранное, история запусков, история поиска, кэш базы, MCP-сервер.
Работает локально: веб-интерфейс на `http://127.0.0.1:8797`, наружу ничего не отдаёт.

## Что нужно на машине

- Windows 10/11 x64.
- Платформа 1С:Предприятие 8.3/8.5 (лончер сам находит установленные платформы).
- Python **3.11–3.12** x64 (например, [python.org](https://www.python.org/downloads/windows/) —
  при установке отметить «Add python.exe to PATH»).

## Установка (один раз)

1. Распаковать архив в папку без пробелов и кириллицы в пути, например `C:\BaseLauncher`.
2. Запустить `install.cmd` — создаст `.venv` рядом с программой и поставит зависимости
   (`fastapi`, `uvicorn`, `pywin32`). Нужен интернет; если у вас прокси — заранее
   `set HTTPS_PROXY=...`.
3. Запустить `BaseLauncher.cmd` — откроется окно приложения.

Порт по умолчанию **8797**. Другой порт: `set BL_PORT=8800` перед запуском (или в свойствах
ярлыка). Если порт занят, сервер скажет об этом в `data/server.log`.

## Автозапуск с Windows

`install-autostart.cmd` — кладёт ярлык `BaseLauncher` в автозагрузку пользователя
(`%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup`). Убрать — удалить ярлык оттуда.

## Где лежат данные

Всё локальное — в папке `data` рядом с программой:

- `data/config.json` — свои настройки баз (имя, описание, логины, пароли, избранное, режим,
  разовые ключи). Создаётся при первом запуске. **Пароли не в открытом виде**: обфускация
  XOR+base64 с ключом от имени машины и пользователя — при копировании на другую машину
  значения просто не расшифруются, и пароль надо ввести заново.
- `data/launches.log`, `data/focus.log`, `data/server.log` — журналы запусков и работы.
- `data/errors/` — снимки окон при ошибках запуска.

При обновлении версии папку `data` **не трогать** — она совместима, новые поля добавятся сами.

## Список баз

Базы берутся из штатного файла 1С `%APPDATA%\1C\1CEStart\ibases.v8i` — того же, что читает
платформа и SM. База, добавленная в лончере, появляется и в штатном стартере 1С,
и наоборот. Папки дерева — оттуда же.

## Пользователи базы (COM)

Кнопка **COM** в настройках базы подтягивает список пользователей информационной базы через
COM-подключение (нужны логин/пароль с правами администрирования ИБ). Основной путь —
`ПользователиИнформационнойБазы.ПолучитьПользователей()`, он не зависит от того, есть ли
в конфигурации справочник «Пользователи». Для файловых баз версия платформы COM должна быть
не ниже версии, которой создана база.

## MCP-сервер (для агентов)

Лончер умеет отдавать себя как MCP-инструменты: `POST http://127.0.0.1:8797/mcp`,
JSON-RPC 2.0 (`tools/list`, `tools/call`). Инструменты: состояние баз, запуск, настройки,
пользователи, кэш, перенос по папкам, проверка платформы. Пароли наружу не отдаются.
Отдельный stdio-вариант — `mcp_server.py`.

## Обновление

1. Закрыть приложение (`⟳ перезапустить` не нужно — просто закройте окно и сервер:
   `POST /api/shutdown` либо закрытие окна из трея).
2. Распаковать новую версию поверх, **сохранив** папку `data` и файл `.venv` (или пересоздать
   `.venv` через `install.cmd`).
3. Запустить `BaseLauncher.cmd`.

## Удаление

Закрыть приложение и удалить папку. Автозапуск — удалить ярлык из Startup. Кэши 1С
(`%LOCALAPPDATA%\1C\1cv8`) лончер не создаёт и не удаляет; чистить их можно из контекстного
меню базы.

## Ограничения

- Только Windows (используются Win32 API: окна, сеансы, COM).
- Пароли в конфиге — «защита от дурака», не криптография: файл `data/config.json` не стоит
  выкладывать в общий доступ.
- `ibcmd` не используется: списка пользователей он не отдаёт, а выгрузка конфигурации требует
  пароля ИБ и на больших базах идёт минутами.

## Состав поставки

```
BaseLauncher.cmd        запуск
install.cmd             установка зависимостей в .venv
install-autostart.cmd   ярлык в автозагрузку
boot.py                 запуск/перезапуск сервера и окна
run_server.py           сервер в консоли (для диагностики)
mcp_server.py           MCP в режиме stdio
app/                    REST + веб-интерфейс (static/index.html)
core/                   логика: ibases.v8i, платформы, сеансы, COM, кэш, конфиг
assets/                 иконки
requirements.txt        зависимости
VERSION                 версия сборки
data/                   создаётся при первом запуске (пустая в поставке)
```
