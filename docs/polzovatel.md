# BaseLauncher — подробное руководство пользователя

> Есть exe-сборка без Python — см. [zapusk-exe.md](zapusk-exe.md).

BaseLauncher — программа для работы со списком баз 1С:Предприятие 8. Это замена SM 1.4. Список баз общий с 1С (файл `ibases.v8i`) — всё, что вы видите в стандартном окне выбора базы 1С, видно и здесь, и наоборот: базы и папки, добавленные в BaseLauncher, появятся и в 1С.

Программа состоит из сервера (работает в фоне на вашем компьютере) и окна-интерфейса. Ничего на другие компьютеры не отправляется — сервер слушает только localhost.

---

## 1. Запуск и окно

### Как запускается
- **Автозапуск с Windows** — программа стартует сама (`pythonw boot.py`), поднимает сервер и открывает окно.
- Ярлык в меню «Пуск» делает то же самое.
- Повторный запуск **не создаёт второе окно** — поднимается уже открытое (или спрятанное).

### Управление окном
| Действие | Результат |
|---|---|
| **Ctrl+Shift+S** (в любом месте Windows) | показать окно, если спрятано / спрятать, если видно |
| Левый клик по иконке в трее | то же самое |
| Правый клик по иконке в трее | меню: «Показать», «Скрыть», «Открыть в браузере», «Выход» |
| Закрытие окна крестиком | окно прячется (сервер остаётся в трее) |
| «Выход» в трее | полный выход: закрывается сервер и иконка |

Размер и положение окна запоминаются между запусками. Внизу окна — строка состояния: подсказки о последнем действии и кнопки «перезапустить/закрыть».

## 2. Список баз: как устроен экран

Сверху вниз:

1. **Шапка**: название и версия, поле поиска с историей, фильтры, кнопки `+ база`, `+ папка`, `☰ меню` (справа).
2. **Полоса разовых ключей** (раскрывается по кнопке в шапке): ключи запуска для следующего запуска.
3. **Вкладки**: `Все` · `★ Избранное` · `● Открытые` · `⟲ Недавние` — овальные пилюли, активная залита цветом. Липнут к верху при прокрутке; **каждая вкладка помнит свою позицию в списке**.
4. **Дерево баз** (на вкладке «Все») — папки и базы; либо плоский список на других вкладках/при поиске.

### Строка базы — анатомия
- **Имя базы** (и описание, если задано).
- Справа от имени:
  - `●` зелёная точка — база **открыта сейчас** (хоть из BaseLauncher, хоть из 1С/EDT);
  - `◷` — свежий запуск: синий = сегодня, жёлтый = вчера (с временем последнего запуска);
  - `П` / `К` — режим по умолчанию: Предприятие/Конфигуратор; полупрозрачная `⇢` = «как в шапке».
- Колонка пути: `D:\...` у файловых, `сервер\база` у серверных, URL у веб-баз.
- Кнопки (видны при наведении):
  - `★` — добавить/убрать из избранного;
  - `⚙` — настройки базы (то же: Alt+Enter или последний пункт контекстного меню);
  - `⧉` — копирование реквизитов (см. 2.4);
  - `🌐` — только у веб-баз: открыть адрес в браузере по умолчанию;
  - `Конф` — открыть в Конфигураторе;
  - `Предпр` — открыть в Предприятии;
  - `cmd` — показать полную команду запуска (пароль замаскирован `***`); повторный клик — скрыть.
- Метки проблем: `✖ папки нет`, `✖ exe нет` — база или платформа не найдены на диске.

### 2.1 Клик, двойной клик, клавиатура
- **Один клик по строке — только выбор** (строка подсвечивается). Никакая база от одного клика не запускается.
- **Двойной клик — запуск** базы в её режиме по умолчанию (`П`/`К`), а при `⇢` — в режиме из шапки.
- **Enter** — запуск выделенной строки. Фокус при этом не обязан быть в поиске.
- **Alt+Enter** — открыть настройки выделенной базы.
- **Ctrl+1…4** — переключение вкладок.
- **Esc** — сбросить поиск/фильтр и вернуться к выделенной строке в общем списке.

Двойной клик по кнопкам (`Конф`, `Предпр`) и по метке режима не запускает базу повторно.

### 2.2 Режим запуска
Режим выбирается тремя способами (в порядке приоритета):
1. кнопка, которой запускаете (`Конф`/`Предпр`);
2. метка `П`/`К` в строке базы — **клик по метке циклит** `⇢ → К → П → ⇢` (после «как в шапке» первым выходит Конфигуратор);
3. режим из шапки (если у базы `⇢`).

У кнопки, совпадающей с режимом по умолчанию, есть подсветка. У тонких клиентов и веб-баз кнопка `Конф` недоступна (у них нет конфигуратора) — это ограничение платформы, не ошибка.

### 2.3 Поиск и фильтры
- Поиск в шапке фильтрует на лету по имени и описанию; стрелки в поле — история запросов. Клик по строке в истории повторяет запрос.
- `✕ фильтр` или Esc — сброс; программа сама найдёт выделенную базу в общем дереве и подсветит её.
- Фильтры `⚠ проблемы`, `8.3`, `8.5` — тумблеры: повторный клик по активному снимает его.
- Поиск и фильтры действуют внутри выбранной вкладки.

### 2.4 Копирование реквизитов (`⧉` и часть пунктов контекстного меню)
Копирует в буфер: имя, путь/адрес, `Srvr`/`Ref`, полную строку соединения (`File="…"`, `Srvr="…";Ref="…"` или `ws=URL`). Удобно для тикетов, коллегам, в скрипты.

### 2.5 Перетаскивание
- Базу можно **перетащить в папку** мышью — откроется подтверждение: «из: … → в: …». Переносится только запись в списке (`Folder=` в `ibases.v8i`), сама база на диске не двигается.
- Перетащить на «Без папки» или в корень — убрать из папки.

### 2.6 Вкладки
- **Все** — дерево папок. Папки по умолчанию свёрнуты; раскрытые запоминаются. Кнопки в строке папки: `+ всё` / `− всё` (раскрыть/свернуть вложенные), `＋ папка` (создать подпапку), `▾/▴`.
- **★ Избранное** — базы с включённой звездой; можно перетаскивать в папки, порядок — как в дереве.
- **● Открытые** — что запущено сейчас. Кнопка `Перекл` — переключиться на окно сеанса (если открыты оба режима — появится выбор `→ Предприятие / → Конфигуратор`). Если у сеанса нет видимого окна (например, конфигуратор запущен из EDT в фоновом режиме), честно пишется «нет окна». `↳ список` — найти базу в общем дереве.
- **⟲ Недавние** — по частоте и свежести запусков; `↳ список` — то же самое.

## 3. Запуск базы

### Что происходит при запуске
1. Если база **уже открыта** — предлагается переключиться на её окно, а не запускать второй сеанс.
2. **Предпроверка соединения** (до старта 1С): сервер 1С доступен по сети / файл `1Cv8.1CD` существует / веб-адрес отвечает. Если что-то не так — показывается понятная причина («Сервер 1С:Предприятия не обнаружен», «папки базы нет») и кнопка **«Запустить всё равно»**.
3. Собирается команда запуска с вашими учётными данными и разовыми ключами, процесс стартует, окно базы автоматически поднимается наверх (даже если стартер был поверх).
4. Если процесс 1С упал или показал окно ошибки — **сторож это ловит**: в строке состояния появляется причина, лаунчер сам пробует подходящие платформы и закрепляет рабочую. Первый запуск «незнакомой» базы может занять до минуты из-за этого, дальше — сразу.

### Выбор платформы (клиента 1С)
- **АВТО** (по умолчанию): платформа подбирается из `Version=` в `ibases.v8i`, версии хранилища конфигурации и формата базы; в списке платформ в настройках видно, что именно подставится («▸ АВТО — … сейчас: X · хранилище: Y · формат 1CD: Z»).
- **Закреплённая**: конкретная версия в настройках базы (список сгруппирован: сначала семейства с конфигуратором — 8.3, потом 8.5, потом старые, потом тонкие клиенты; разрядность в строке).
- Если платформы нет на компьютере — диалог предложит: **поставить с шары** (если там есть дистрибутив), **открыть папку дистрибутивов**, **заменить на ближайшую установленную**, **выбрать другую**.
- Веб-базы (публикации) открываются тонким клиентом ровно той версии, какой опубликована база — лаунчер сам читает версию публикации.

### Разовые ключи (панель в шапке)
- **от администратора (UAC)** — первая галочка в панели разовых ключей: отмечаешь её и запускаешь базу любой кнопкой (двойной клик, Предприятие/Конфигуратор) — стартует повышенным. Как и остальные разовые ключи, действует на следующий запуск и не сохраняется.
Для одного следующего запуска, в конфиг не пишутся:
- произвольные ключи запуска (например `/ZDisableV8MemoryLimit`);
- **обработка** — путь к `.epf`/`.erf`, будет передан через `/Execute` (кнопка `…` открывает выбор файла);
- галки `WS`, `Thin` и т.п.

## 4. Настройки базы (⚙, Alt+Enter, контекстное меню)

- **Имя / Описание** — как база называется в списке (имя секции в `ibases.v8i` не трогается).
- **Учётные данные**: пользователь и пароль — **раздельно для Предприятия и для Конфигуратора**. Пароли хранятся в конфиге лаунчера в обфусцированном виде (защита от подглядывания, не криптография; привязаны к этой машине и пользователю Windows). В интерфейсе пароль не показывается — только пометка «пароль сохранён»; поле пустое = «не менять», стереть пароль — соответствующая галка.
- **Платформа** — АВТО или конкретная сборка (дерево по семействам).
- **Режим по умолчанию** — Предприятие/Конфигуратор.
- **Избранное**, **тонкий клиент**.
- **Папка** — перенос базы в папку (то же, что перетаскивание, с подтверждением).
- **Хранилище конфигурации** — путь (`\\…`/`D:\…`/`tcp://…`), пользователь, пароль. По ver-файлу хранилища лаунчер дополнительно определяет версию платформы.
- **Доп. ключи** — постоянные ключи запуска для этой базы.
- Кнопка **авто** у платформы сбрасывает закрепление полностью (exe + семейство + подобранное).

Сохранение — `Сохранить`; отмена — `Отмена` или клик мимо окна.

## 5. Контекстное меню базы (правый клик по строке)

- Запуск: Предприятие / Конфигуратор; переключиться на окно, если открыта.
- **Запустить от администратора** (конфигуратор/предприятие) — разовый запуск с
  повышением прав (UAC-запрос Windows). Нужен, когда 1С требует прав: например,
  публикация базы на веб-сервере из конфигуратора пишет в конфиг Apache/IIS.
  Обычные запуски прав не повышают; в истории запусков помечается «(админ)».
- **Кэш** (три вида, см. раздел 6): очистить кэш программы (конфигурации); сбросить настройки пользователя 1С; очистить общий кэш.
- **COM**: проверить подключение (определить версию сервера), пользователи ИБ.
- **Загрузить базу из .dt** (файловые) — восстановление из выгрузки; перед этим каталог базы переименовывается в бэкап, выбор файла через диалог.
- **Проверить базу данных (chdbfl)** — запускает оконную утилиту проверки 1С.
- **Выгрузить конфигурацию в XML** (файловые) — исходники конфигурации этой базы
  (ibcmd, формат платформы базы) в свой подкаталог указанного каталога. Открытые базы не
  выгружаются (нужна исключительная блокировка). Каталог запоминается (до 3 последних, в
  config.json) и предлагается при следующей выгрузке/загрузке.
- **Загрузить конфигурацию из XML** (файловые) — три режима:
  - *только изменённое* — файлы, изменившиеся с прошлой выгрузки этой базы (сравнение по
    времени/размеру с манифестом, который пишется при каждой выгрузке);
  - *заданные объекты / файлы* — вручную: имена вида `Справочник.Номенклатура`
    (разворачиваются в файл + поддерево: формы, макеты) или относительные пути;
  - *полная* — замена всей конфигурации базы (с подтверждением).
  Чекбокс «обновить БД» применяет конфигурацию к базе после загрузки. Исходники ищутся в
  подкаталоге «<имя базы>» указанного каталога (как раскладывает выгрузка), иначе в самом каталоге.
- Копирование реквизитов (те же пункты, что у `⧉`).
- **Удалить из списка** — секция базы убирается из `ibases.v8i` (сами данные на диске не трогаются; перед удалением показывается путь).
- **Настройки…** (`Alt+Enter`).

Меню папки: переименовать, удалить папку (если пуста), `＋ папка` (подпапка).

## 6. Кэш 1С — три уровня

1С хранит служебные данные каждой базы в трёх местах, по GUID базы:

| Уровень | Где лежит | Что внутри | Когда чистить | Последствия |
|---|---|---|---|---|
| **Кэш программы (конфигурации)** | `%LOCALAPPDATA%\1C\1cv8\<guid>` | скачанная конфигурация, кэш форм, кэш хранилища | база «странно» себя ведёт, ошибки форм, после обновлений | нет — пересоздаётся сам |
| **Настройки пользователя** | `%APPDATA%\1C\1cv8\<guid>` | `1cv8.pfl`, `def.usr`: размеры окон, настройки форм, колонок | «слетел» интерфейс, кривые формы | сбрасываются интерфейсные настройки базы |
| **Общий (все пользователи ПК)** | `%PROGRAMDATA%\1C\1cv8\<guid>` | общий кэш | редко (обычно пуст) | нет |

Данные самой базы (1Cv8.1CD) очисткой кэша не затрагиваются никогда. Сеансы 1С на время очистки лучше закрыть — занятые файлы пропустятся.

Очистка одного уровня конкретной базы — через контекстное меню. Для всего сразу и с выбором — меню `☰` (раздел 7).

## 7. Меню ☰ — обслуживание

Кнопка `☰` в правом краю шапки. Здесь команды обслуживания компьютера, а не одной базы.

### 7.1 Платформы: список
Все установленные платформы 1С (включая 8.2, 8.1 и «тонкие» сборки): версия, семейство, разрядность, **размер на диске**, **компоненты** (конфигуратор / тонкий клиент / сервер / COM), и **кто на ней сидит** — сколько баз закреплено/подобрано/указано в `Version=`. У каждой строки:
- **перевести базы…** — открывает окно перевода (7.3), сразу с фильтром по этой платформе;
- **папка** — открыть каталог версии в проводнике;
- **удалить** — удаление одной платформы (с защитой, см. 7.2).

### 7.2 Удалить ненужные платформы (выбрать)
Окно с чекбоксами по всем платформам, поиск, **выбрать всё / снять всё / переключить выбор** (в рамках текущего поиска). Платформы, на которых есть базы или **живые сеансы**, показаны с галкой, но заблокированы — сначала переведите базы (7.3) и закройте сеансы. Удаление из Program Files требует подтверждения UAC. Итог — одним сообщением «удалены / НЕ удалены (почему)».

### 7.3 Перевести базы на другую платформу
Массовый перевод баз с одной платформы на другую (например, все 8.2 → 8.3.27):

1. **Откуда** — семейство (8.3, 8.5…) или точная версия. Ниже показываются базы этой платформы.
2. **Хранилище** — фильтр по конкретным хранилищам из данных этих баз: UNC-пути `\\…`, локальные `D:\…`, серверные `tcp://…`. В списке показывается полный адрес хранилища и сколько на нём баз («1 база / 2 базы / 6 баз»); очень длинные адреса сжимаются многоточием в середине — полный виден в подсказке при наведении. У одного хранилища может быть несколько баз — фильтр выбирает их все разом; есть пункт «без хранилища». В подписи также версия платформы по ver-файлу, если читается.
3. **Поиск** по имени, чекбоксы по базам, **выбрать всё / снять всё / переключить выбор** — всё в рамках текущих фильтров.
4. Колонки в списке: `Version=` (что записано в `ibases.v8i`) и **«по хранилищу»** — версия платформы по ver-файлу хранилища конфигурации (для tcp:// честно пишется «не читается»). Открытые сейчас базы помечены «(открыта)».
5. **На какую платформу** — целевой список (тонкие сборки помечены).
6. **Перевести выбранные** → подтверждение со списком → готово.

Что делает перевод: закрепляет exe платформы в настройках лаунчера **и** пишет `Version=` в `ibases.v8i` — то есть базу откроет и штатный лаунчер 1С. Сами базы на диске не меняются. Перед переводом закройте сеансы переводимых баз.

### 7.4 Мёртвые кэши (не привязаны к базам)
Каталоги кэша 1С, у которых больше нет базы с таким ID (остались от удалённых баз; на «замусоренных» машинах набираются гигабайты). Окно: чекбоксы, **поиск по GUID**, размер/дата каждого, где лежит (LOCALAPPDATA/APPDATA/PROGRAMDATA), **выбрать всё / снять всё / переключить выбор**, сводка «выбрано N · X МБ». Удаляются только выбранные, с подтверждением и суммой. Данные существующих баз не затрагиваются.

### 7.5 Очистить кэш по базам (выбрать)
Все базы, у которых есть кэш, с размерами (отсортировано по величине): чекбоксы, поиск, выбрать/снять/переключить, **тип кэша** (кэш программы / настройки пользователя / оба), сводка освобождаемого места. Знак `+` у размера = «не меньше» (обход огромного кэша ограничен по времени).

### 7.6 Кэш пользователя 1С (все базы)
Суммарная очистка кэша по всем базам сразу — для быстрой уборки, без выбора.

## 8. Добавление и удаление

- **`+ база`** — новая файловая база (имя + путь к каталогу с `1Cv8.1CD`) или серверная (`Srvr` + `Ref`). Запись появляется в `ibases.v8i`, т.е. и в 1С.
- **`+ папка`** — новая папка с выбором родителя (дерево). `＋ папка` в строке папки — подпапка.
- **Удаление базы из списка** — только запись в `ibases.v8i`; файлы базы не трогаются, путь показывается перед удалением.
- Перед записью в `ibases.v8i` автоматически делается дневной бэкап (`ibases.v8i.bak-ГГГГММДД`).

## 10. Если что-то не работает

| Симптом | Что делать |
|---|---|
| «Ничего не произошло» при запуске | строка состояния внизу: там причина (предпроверка, версия платформы, «нет окна»). Кнопка `cmd` покажет команду запуска |
| Появилось окно ошибки 1С | смотрите строку состояния — сторож ловит причину и часто сам подбирает рабочую платформу |
| База «тормозит/глючит» | контекстное меню → «Очистить кэш программы (конфигурации) этой базы» |
| Слетели окна/формы в базе — это нормально после сброса настроек пользователя | — |
| Окно лаунчера потерялось | Ctrl+Shift+S или клик по иконке в трее |
| Базы нет в списке | `+ база` — она осталась на диске, просто записи нет |
| Платформа не находится | в настройках базы кнопка диалога предложит поставить с шары или заменить |
| Не открывается серверная база | версия клиента должна совпадать с версией сервера (8.3 ≠ 8.5). Запустите с АВТО — лаунчер подберёт; или COM-проверка в контекстном меню определит версию сервера |
| Пароль «слетел» после переноса на другой компьютер | так задумано: пароли привязаны к машине. Введите заново в настройках базы |

## 11. Где что хранится

- Список баз и папок — общий с 1С файл `ibases.v8i`.
- Настройки лаунчера, учётки, пароли (обфусцированы) — `data/config.json` в каталоге программы.
- История запусков — `data/launches.log`.
- Журнал действий (что запускали, что меняли и чистили; пароли в нём замаскированы) — `data/audit.log`, автоматически обрезается по 2 МБ.
- Манифесты XML-выгрузок (для режима «только изменённое») — `data/manifests/<guid>.json`; запомненные каталоги выгрузки — `config.json` → `dump_paths`.
- Ничего из этого в git/сеть не отправляется.
